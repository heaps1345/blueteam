Module 2 — Lesson

Before you type a single command, know what you're typing

A quick primer on shell basics and what each tool category is actually doing, so the walkthrough worksheet isn't just copy-paste — you'll know why each command exists and what its output is telling you.

01

Reading a command before you run it

Every command you'll type in this module follows the same basic shape. Once you can read this shape, unfamiliar commands stop being scary — you can usually guess roughly what they do.

strings -el beacon.exe | less
program being run
flag / option (changes behavior)
argument (what it acts on)
pipe — sends output of one program into another

The program

The first word is always the program being executed — strings, file, peframe. If you're not sure what a program does, man strings opens its manual page, and strings --help usually gives a quicker summary.

Flags / options

Anything starting with - or -- changes how the program behaves without changing what it acts on. -e and l combined as -el tells strings to extract little-endian wide-character text specifically.

Arguments

Usually the file or target the command acts on. In strings -el beacon.exe, the file is the argument — without it, most tools either wait for input or do nothing.

02

The pipe — chaining tools together

The single most useful symbol in the terminal is | — it takes the output of the command on the left and feeds it as input to the command on the right.

$ strings beacon.exe # dumps every printable string — could be thousands of lines
KERNEL32.dll
VirtualAlloc
... (hundreds more lines scroll past instantly)
$ strings beacon.exe | less # same output, but paged so you can scroll it
$ strings beacon.exe | grep -i "kernel" # filters to only lines containing "kernel"

Three commands worth knowing well: less turns a wall of output into something scrollable (press q to quit, / to search forward). grep filters lines matching a pattern — grep -i makes the match case-insensitive. head and tail show just the first or last N lines, useful when you only need a quick peek.

03

sudo and why some tools need it

Most of the analysis commands in this module (file, strings, peframe, exiftool) just read a file you already own, so they don't need elevated privileges. You'll occasionally see sudo in front of a command elsewhere in Kali — it means "run this one command as the root/administrator user." Use it only when a tool specifically requires it (usually anything touching network interfaces or installing packages), not as a default habit.

04

What each tool category is actually for

Before running the worksheet commands, it helps to know which question each tool is answering. None of these tools "detect malware" by themselves — they each surface one type of evidence, and you combine them.

ToolQuestion it answersWhat it can't tell you
sha256sumWhat is this file's unique fingerprint?Nothing about content or behavior — purely an identity check.
fileWhat format/architecture is this file?Nothing about whether it's malicious — a PE file is just a PE file.
exiftoolWhat metadata did the build process leave behind?Absence of metadata is suspicious but not proof of anything on its own.
stringsWhat readable text is embedded in the file?Encoded/encrypted content won't show up as readable text at all.
peframeWhat do the PE structure, sections, and imports look like?It flags patterns — it doesn't confirm intent, you still verify manually.
binwalk -EWhere in the file is randomness concentrated?High entropy means "could be encoded/compressed," not "is malicious."
VirusTotalHave other engines/analysts seen this exact file before?A new, never-seen file will show no matches even if it's harmful.
Joe SandboxWhat does this file actually do when executed?Sandbox-aware malware may behave differently than it would on a real target.
05

Your very first three commands, narrated

This is the exact sequence you'll type at the start of the worksheet, slowed down so you can see what's happening at each keystroke.

1 Navigate to where your file actually is. cd ~/Desktop (or wherever you saved it) changes your current directory. Run ls afterward to confirm beacon.exe is actually listed — if it's not there, the next commands will fail with "No such file or directory."
2 Hash it. sha256sum beacon.exe reads every byte of the file and produces a 64-character hex string. This runs instantly for a small file. Copy this value somewhere safe immediately — you'll reuse it in the VirusTotal stage.
3 Identify the format. file beacon.exe reads just the first few bytes (the header) rather than the whole file, which is why it returns instantly even on large files. It's comparing those header bytes against a known database of file signatures (called "magic numbers") to guess the format.
